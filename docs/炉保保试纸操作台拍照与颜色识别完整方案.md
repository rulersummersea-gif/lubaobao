# 炉保保试纸操作台、拍照与颜色识别完整方案

版本：V0.1 评审稿
日期：2026-08-06
状态：待业务、试纸和水处理专业人员确认

## 1. 方案目标

炉保保采用一个巡检入口，将软化水和炉水试纸放入统一操作台后拍摄一张照片。识别模块只输出试纸读数、候选色阶、置信度和质量信息，不直接判断合格、不直接生成加药或排污建议。后端规则引擎根据锅炉档案、压力、水处理方式和已确认标准分别判断软化水和炉水。

本方案参考 Zhang 等人在 PLOS ONE 发表的论文《A novel systems solution for accurate colorimetric measurement through smartphone-based augmented reality》（DOI: 10.1371/journal.pone.0287099）。论文验证了以下组合的可行性：

1. 四角 ArUco 标记定位参考板。
2. 通过视频画面引导用户接近垂直、固定距离拍摄。
3. 使用参考板四边的连续 HSV 色带覆盖较宽颜色范围。
4. 使用一阶空间变化系数模型修正手机、光照和板内不均匀照明。
5. 在 pH 试纸上使用 CIE 颜色与相邻色阶插值读取数值。

论文在 pH 实验中报告算法平均绝对误差约 0.12，人工读取约 0.37；但其验证对象、手机数量、试纸种类和实验环境与炉保保不同，不能直接视为本项目准确率。炉保保必须对每种试纸、每个批次和实际锅炉水样独立验证。

## 2. 产品边界

### 2.1 V1 检测项目

| 槽位 | 水样 | 项目 | 启用规则 |
| --- | --- | --- | --- |
| S1 | 软化水 | pH | 默认启用 |
| S2 | 软化水 | 硬度 | 默认启用，核心项目 |
| B1 | 炉水 | pH | 默认启用 |
| B2 | 炉水 | 总碱度 | 默认启用 |
| B3 | 炉水 | 磷酸根 | 使用磷酸盐方案时启用 |
| B4 | 炉水 | 亚硫酸根 | 使用亚硫酸盐除氧方案时启用 |
| B5 | 炉水 | 氯离子 | 作为浓缩趋势辅助项启用 |
| X1 | 预留 | 后续项目 | V1 不要求放置试纸 |

炉水硬度不作为日常核心项目。电导率或 TDS 是炉水浓缩与排污控制的重要指标，但不适合普通颜色试纸识别，系统应预留仪表读数或仪表屏幕数字识别能力。

### 2.2 动态检测组合

锅炉档案中的处理方案采用三态配置：`enabled`、`disabled`、`unknown`。

- `enabled`：对应槽位必须放置试纸并提交读数。
- `disabled`：对应槽位可为空，不参与结果判断。
- `unknown`：小程序提醒方案尚未确认，后台服务人员确认前不把零值判为异常。

### 2.3 AI 输出边界

识别服务只输出：

- 项目编码和水样类型；
- 第一候选色阶及数值；
- 第二候选色阶及数值；
- 置信度；
- 是否需要人工确认；
- 图像、色卡、槽位和显色时间质量；
- 操作台、试纸批次、算法和标定版本。

合格判断、风险诊断、处置建议和复测任务由业务后端完成。

## 3. 操作台总体设计

### 3.1 推荐结构

第一版建议采用 A4 横向或约 320 mm x 230 mm 的哑光硬质操作台。操作台由三层组成：

1. 底板：中性灰哑光 PVC、ABS 或经过验证的硬质卡板。
2. 可更换校准卡纸：四边色带、离散校准块、板卡编号和版本二维码。
3. 可更换湿区托盘：8 个试纸槽、挡水边和吸水区，防止液体污染色卡。

示意布局：

```text
┌──────────────────────────────────────────────────────┐
│ [A0]  顶部连续色带 H + 离散校准块               [A1] │
│ 左侧                                                 右侧 │
│ 色带  S1  S2  B1  B2  B3  B4  B5  X1             色带 │
│       │   │   │   │   │   │   │   │                    │
│       │   │   │   │   │   │   │   │                    │
│       项目比色阶与试纸显色区处于相邻局部区域             │
│ [A2]  底部连续色带 H + 板卡/批次二维码             [A3] │
└──────────────────────────────────────────────────────┘
```

### 3.2 四角定位码

- 使用 OpenCV ArUco `DICT_4X4_50`。
- 四角分别使用 ID 0、1、2、3，禁止重复。
- 单个码建议 28-32 mm，外侧保留至少 5 mm 白色静区。
- 定位码放在同一平面，不能被透明盖板折射或被试纸遮挡。
- 黑白定位码与彩色色带分开印刷和质检。
- 生产验收应检查尺寸、边缘完整性、黑白反差和耐磨性。

四个定位码提供 16 个角点。算法据此识别操作台方向、计算相机姿态、做透视校正，并把操作台转换为固定像素尺寸。

### 3.3 全局颜色校准区

采用“连续色带 + 离散色块”的混合设计。

连续色带参考论文布局：

- 顶部和底部：Hue 连续变化色带，方向相反或做镜像校验。
- 左侧：Hue 与 Saturation 变化色带。
- 右侧：Hue 与 Value 变化色带。

离散色块至少包括：

- 白、浅灰、中灰、深灰、黑；
- 红、绿、蓝、青、品红、黄；
- 接近实际7项试纸主要显色范围的定制色块；
- 左右或上下重复色块，用于检测局部阴影和照明不均。

连续色带负责为一阶空间颜色模型提供大量采样点，离散色块负责质量验证，不能互相替代。

### 3.4 项目比色阶

每个有效槽位旁放置该项目的实体比色阶，要求：

- 色阶与试纸品牌、型号、批次绑定；
- 色阶顺序与数值方向固定；
- 每个色块建议不小于 8 mm x 8 mm；
- 色块与湿试纸保持隔离，不能被水滴污染；
- 每个色块在生产时记录实测 CIELAB 值；
- 板卡二维码关联比色阶版本、试纸批次和有效期。

实体比色阶用于同图局部比较，但最终模型不能只学习印刷色块。印刷油墨与湿试纸的反射特性不同，必须用标准溶液反应后的真实试纸建立颜色分布。

### 3.5 试纸手持端标记

固定槽位是项目识别的主依据，试纸手持端标记是防错校验。

- 标记位于干燥手持端，远离浸水线和显色区。
- 使用黑白编码和不对称方向箭头，不使用彩色墨水。
- 标记由生产环节印制或使用独立夹片，不由用户手画。
- 标记内容至少表示项目编码和方向，可选加入批次短码。
- 标记识别结果必须与槽位一致，否则提示放错试纸。

### 3.6 材料和维护

- 使用中性灰、哑光、耐水、低反射材料。
- 不使用光面覆膜、高反光亚克力或透明胶带覆盖色块。
- 校准卡纸采用可更换结构，湿区托盘独立清洁或更换。
- 色卡受污染、褪色、折痕或超过有效期时禁止继续自动识别。
- 每张卡纸设置唯一 `board_id`、`board_version` 和生产批次。

## 4. 色卡生产与数字化

论文指出设计文件颜色与实际打印颜色存在明显差异，因此不能把设计文件 RGB 值直接当作实体色卡真值。

生产流程建议：

1. 使用同一印刷设备、油墨、纸张和表面工艺生产一批卡纸。
2. 使用色差仪或分光测色仪测量离散色块的 CIELAB 值。
3. 在受控灯箱内使用参考相机数字化连续色带。
4. 生成该批卡纸的标准数字参考图和颜色采样表。
5. 将参考图、采样点和实测值绑定 `board_version`。
6. 抽检同批卡纸间色差，超出生产公差的卡纸剔除。
7. 做水滴、擦拭、温湿度、紫外和使用周期老化测试。

研发原型阶段可以先采用论文的“扫描打印卡纸并建立中间颜色系统”方法；正式产品阶段应升级为仪器实测和批次质检。

## 5. 试纸操作与显色时间

单张照片方案成立的前提是所有启用试纸存在可重叠的有效读数时间窗口。

每种试纸需配置：

- 取样点；
- 浸泡或滴加方式；
- 浸泡时间；
- 去除余水方式；
- 显色开始时间；
- 推荐读数时间；
- 最早和最晚有效读数时间；
- 温度适用范围；
- 干扰物和异常颜色说明。

小程序根据各项目时间窗口倒排操作顺序。显色时间长的先操作、时间短的后操作，使最终拍照时间同时落入所有项目有效窗口。

若无法形成共同窗口，产品必须改为分阶段拍照，不能通过算法补偿已经过时或尚未完成的化学反应。

## 6. 小程序拍照逻辑

### 6.1 拍照前

1. 读取当前锅炉、水处理方案和本次必测槽位。
2. 校验材料包、试纸批次和操作台版本。
3. 按时间计划引导用户完成取样和试纸操作。
4. 提示用户将试纸放入固定槽位。
5. 检查所有必测项目计时器是否进入共同拍照窗口。

### 6.2 实时取景引导

论文采用 ArUco + PnP 计算相机姿态，并引导用户移动到操作台正上方。炉保保建议目标姿态为接近 90 度俯拍。

取景界面实时显示：

- 四角框：红色表示未对齐，绿色表示合格；
- 移动方向：左、右、前、后、靠近或远离；
- 倾斜提示：请保持手机与操作台平行；
- 光照提示：过暗、过亮、反光或左右照明不均；
- 完整性提示：缺少试纸、放错槽位或标记不可见；
- 时间提示：距离统一有效窗口结束的剩余时间。

连续稳定合格约 0.8-1.0 秒后自动拍照，减少按快门造成的抖动。

### 6.3 小程序实施分期

论文使用原生 iOS 实现实时姿态计算。微信小程序的计算和相机帧能力需要分期落地：

- V1：固定取景框和拍照后服务器质量检查；不合格立即返回重拍。
- V1.5：使用相机帧监听和轻量模型实时检测四角与完整性。
- V2：使用 WASM/OpenCV 或原生能力实现 ArUco、PnP 和自动快门。

无论客户端是否实时检测，后端必须重新执行完整质量门禁，不能信任客户端结论。

### 6.4 图片保存

- 上传原始照片，不上传截图或预览缩略图。
- 保存原图、裁正图、校正图和每个试纸 ROI。
- 裁掉操作台外区域，减少无关场景和人员隐私信息。
- 保存手机型号、系统、小程序版本、图片尺寸和拍照时间。
- 禁止滤镜、美颜和二次编辑。

## 7. 图像质量门禁

质量检查分为文件级、操作台级、试纸级和颜色级。

### 7.1 文件级

- 文件格式和大小合法；
- 分辨率满足每个试纸显色区的最低像素要求；
- 图片没有严重压缩、解码失败或异常旋转；
- 全图清晰度、亮度和对比度达到工程阈值。

### 7.2 操作台级

- 四个 ArUco 全部识别；生产阶段不建议只依赖三个角点继续。
- 操作台完整处于画面内，四边未裁切。
- 操作台占画面比例合理。
- 相机姿态和拍摄距离处于允许范围。
- 透视校正后的长宽比和实际尺寸一致。

### 7.3 试纸级

- 必测槽位存在试纸；
- 手持端编码与槽位一致；
- 试纸方向正确、平整、没有重叠；
- 显色区没有大水珠、气泡、污染和严重色斑；
- 显色时间处于有效窗口。

### 7.4 颜色级

- 白色和浅色块没有通道过曝；
- 黑色和深色块没有严重欠曝；
- 左右重复色块色差未超过工程阈值；
- 色彩校正模型残差未超过工程阈值；
- 试纸 ROI 内颜色均匀度满足要求。

门禁输出分为：

- `pass`：允许识别。
- `review`：允许生成候选值，但必须人工确认。
- `reject`：不输出读数，必须重拍或重新检测。

## 8. 图像处理与颜色校正算法

### 8.1 预处理

1. 读取图片方向并统一为标准方向。
2. 检测 ArUco ID 和16个角点。
3. 对角点做亚像素级优化。
4. 根据实体坐标计算单应矩阵。
5. 将操作台透视校正为固定尺寸标准图。
6. 根据标定参数选择是否执行镜头畸变校正。

### 8.2 一阶空间变化颜色模型

论文采用以下思路分别校正 R、G、B 三个通道：

```text
Reference_c(x,y) = alpha_c(x,y) * Image_c(x,y) + beta_c(x,y) + error
```

其中：

```text
alpha_c(x,y) = a1*x + a2*y + a3
beta_c(x,y)  = b1*x + b2*y + b3
```

四边连续色带提供大量“拍摄值 - 标准值 - 空间位置”样本。论文每隔10像素取样，并使用普通最小二乘拟合。炉保保建议采用稳健加权最小二乘或 RANSAC，降低色带磨损、水滴、反光和局部污染对模型的影响。

校正流程：

1. 从四边色带按固定间距采样。
2. 排除过曝、阴影、污染和异常像素。
3. 读取当前卡纸版本的标准参考值。
4. 分别拟合 R、G、B 的 `alpha` 和 `beta` 空间平面。
5. 对整张裁正图执行空间相关颜色转换。
6. 用未参与拟合的离散色块计算校正残差。
7. 残差过大则拒绝识别。

一阶模型作为 V1 基线。二阶模型、三维查找表和神经网络颜色校正只有在独立验证集上显著改善且不过拟合时才升级。

### 8.3 颜色空间

建议同时保留以下特征：

- 线性 RGB 与归一化 RGB；
- HSV；
- CIE XYZ 与 `x,y` 色度坐标；
- CIELAB；
- CIEDE2000 色差；
- 试纸颜色与邻近局部参考色块的相对差值。

论文在 pH 插值中使用 CIE 1931 `x,y` 色度坐标。炉保保不预设所有项目都采用同一颜色空间，而是在每个项目的独立验证中选择误差最小且稳定的特征组合。

## 9. 试纸定位与颜色提取

透视校正后，每个槽位的理论坐标固定。算法按以下顺序处理：

1. 在槽位范围内检测试纸轮廓和手持端编码。
2. 校验试纸方向、长度、宽度和槽位身份。
3. 根据试纸型号模板定位显色区。
4. 从显色区边缘向内收缩，避免毛细扩散和边缘渗色。
5. 检测并屏蔽高光、水珠、气泡、阴影和污染像素。
6. 将 ROI 划分为多个子区，计算颜色中位数、截尾均值和均匀度。
7. 保存 ROI 图和颜色特征，供后台复核与后续训练。

不建议只读取一个像素，也不建议简单读取整个显色区平均 RGB。

## 10. 读数算法

### 10.1 V1：离散色阶识别

每个项目、每个试纸批次建立独立色阶模型。训练数据来自标准溶液或可靠参考方法确认的真实反应试纸。

每个色阶保存：

- 中心颜色；
- 颜色协方差和正常波动范围；
- 不同手机、光照和显色时间下的分布；
- 相邻色阶的决策边界；
- 容易混淆的颜色和干扰情况。

识别时计算当前 ROI 与每个色阶分布的距离。建议比较：

- CIEDE2000 色差；
- 马氏距离；
- CIE `x,y` 距离；
- 经过验证的轻量分类器或有序分类模型。

输出距离最近的第一候选和第二候选。第一版只输出试纸原有色阶，不制造超出试纸能力的小数精度。

### 10.2 V1.5：受控插值

论文使用两个最近参考点的反距离加权插值得到超出印刷色阶分辨率的 pH 数值。炉保保只有满足以下条件才允许启用插值：

1. 项目颜色随浓度呈稳定单调轨迹。
2. 标准溶液覆盖两个色阶之间的多个中间点。
3. 不同试纸批次、手机和时间窗口均验证通过。
4. 插值结果相对于参考方法具有明确误差范围。
5. 产品页面同时展示测量不确定度，不能把插值值描述为实验室精度。

不满足条件的项目继续输出离散色阶。

### 10.3 V2：数据驱动模型

积累足够样本后，可以使用轻量机器学习或深度学习模型处理非线性颜色轨迹、复杂污染和多手机差异。但模型仍必须：

- 按项目和试纸批次管理；
- 使用标准方法真值训练；
- 保留传统颜色距离基线；
- 对分布外样本拒绝输出；
- 输出可解释的候选色阶和置信度；
- 不直接生成锅炉处置结论。

## 11. 置信度与自动确认

最终置信度由以下子分数组成：

```text
confidence = F(
  marker_quality,
  pose_quality,
  image_quality,
  color_correction_quality,
  strip_identity_quality,
  roi_uniformity,
  timing_quality,
  batch_match_quality,
  class_margin
)
```

其中 `class_margin` 表示第一候选与第二候选之间的区分程度。

建议初始策略：

- 高置信度：自动填入第一候选，用户确认。
- 中置信度：同时展示两个候选，让用户选择。
- 低置信度：不输出读数，要求重拍、重新检测或人工比色。
- 关键阈值附近：即使置信度较高，也可按业务规则要求人工确认。

具体阈值必须由验证数据确定，不能在研发阶段写死为生产标准。

## 13. 训练与验证方案

### 13.1 真值来源

- 使用标准溶液覆盖每个试纸色阶和关键边界。
- 使用对应国标方法、实验室方法或经过校准的参考仪器确认真值。
- 真实锅炉水样需记录温度、浑浊、颜色、药剂和可能干扰物。
- 同一水样由多条试纸重复测量，不能只保留最好的一张。

### 13.2 数据矩阵

验证至少覆盖：

- 每个检测项目和全部色阶；
- 色阶之间的关键中间浓度；
- 至少多个试纸生产批次；
- 主流 iPhone、华为、小米、OPPO、vivo 和低配置设备；
- 受控照明、自然光、偏暖、偏冷、轻微阴影和轻微反光；
- 不同操作人员；
- 显色窗口内不同时间点；
- 清洁卡纸、轻度磨损和临近更换期卡纸。

训练集与验证集必须按试纸批次、手机或采集批次隔离，避免同一批连拍图片同时进入训练和验证造成虚高准确率。

### 13.3 建议工程指标

以下是灰测目标，不是已达成结果：

- 四角定位成功率不低于 99%。
- 合格照片中必测槽位识别率不低于 99%。
- 离散色阶完全一致率目标不低于 90%。
- 允许相邻一档的一致率目标不低于 98%。
- 关键合格边界的异常检出率目标不低于 95%。
- 低置信度样本错误自动确认率低于 1%。
- 同一水样跨已支持手机型号结果保持在同一色阶或预先约定误差内。

正式上线阈值应由样本量、风险评估和专业人员共同确认。

## 14. 开发阶段

### 阶段0：化学与操作验证

- 确定试纸品牌、型号、色阶和批次。
- 核对每种试纸操作方法和显色时间。
- 验证7项是否存在共同拍照窗口。
- 确认磷酸根、亚硫酸根的动态启用规则。

### 阶段1：操作台原型

- 制作1:1纸质原型和哑光硬板原型。
- 验证四角定位、8槽摆放、防水和手机画面占比。
- 生产第一批可数字化的校准卡纸。

### 阶段2：传统算法基线

- 完成 ArUco、透视校正、质量门禁和一阶空间颜色校正。
- 建立每个项目的离散色阶模型。
- 后台支持 ROI、AI值和人工真值审核。

### 阶段3：灰测

- 小程序继续允许人工确认所有读数。
- 收集真实手机、现场光照、试纸批次和锅炉水样。
- 统计每项目准确率、混淆色阶、重拍率和手机差异。

### 阶段4：辅助识别上线

- 高置信度自动填写，用户确认。
- 中置信度显示两个候选。
- 低置信度重拍或人工比色。
- 逐项目开放，不要求7项同时达到同一进度。

### 阶段5：持续标定

- 新手机型号验证。
- 新试纸批次快速标定。
- 操作台色卡寿命监控。
- 模型漂移、异常漏报和人工修正率监控。

## 15. 主要风险与控制

| 风险 | 控制措施 |
| --- | --- |
| 试纸没有共同显色窗口 | 调整操作顺序；无法重叠时分阶段拍照 |
| 不同手机颜色差异 | 每张照片内置参考色校正；按手机验证 |
| 色卡打印批次差异 | 实体测色、批次档案、抽检和可更换卡纸 |
| 水滴污染色卡 | 湿区托盘、挡水边、色卡与试纸物理隔离 |
| 反光和局部阴影 | 哑光材料、左右重复色块、姿态引导和质量门禁 |
| 试纸放错位置 | 固定槽位 + 手持端黑白码双重校验 |
| 药剂方案不同 | 磷酸根和亚硫酸根按锅炉档案动态启用 |
| 插值造成虚假精度 | V1只输出原始色阶；验证后逐项目开放插值 |
| AI误判直接影响处置 | AI只读数；后端规则判断；低置信度人工确认 |

## 16. 本轮需要确认的决策

1. 操作台保留8槽，V1使用7槽并预留1槽。
2. 炉水硬度不进入日常固定项目。
3. 磷酸根、亚硫酸根按实际药剂方案启停。
4. 采用四角 ArUco + 四边连续色带 + 离散校准块。
5. 每个项目保留实体比色阶，并绑定试纸品牌和批次。
6. V1只识别离散色阶，不默认插值成连续数值。
7. 小程序初期拍照后检查，后续再升级实时 AR 引导。
8. AI只输出读数和置信度，业务后端负责标准判断。
9. 先确定试纸和显色时间，再冻结操作台尺寸和色卡布局。
