## 一、项目定位

**炉保保智能**是一个面向**工业锅炉水质检测**的 SaaS 化产品，GitHub 仓库 `rulersummersea-gif/lubaobao`。

核心业务：

1. 企业锅炉房现场人员通过一个检测入口，把两类水样试纸放入统一操作台拍照：**软化器出口软化水检测pH、硬度；锅水/炉水检测pH、磷酸根、亚硫酸根、总碱度、氯离子、硬度**；
2. 通过手机端（微信小程序为主、H5 灰测端为辅）录入/识别读数；
3. 后端依据 **GB/T 1576《工业锅炉水质》** 标准，按锅炉额定压力分段（0–1.0 / 1.0–1.6 / 1.6–2.5 / 2.5–3.8 MPa 共 4 段）匹配限值，判断是否异常；
4. 异常组合触发**动态诊断**（5 类组合规则，见下），给出现场处置建议（排污、加药、软水器检查）和**复测任务闭环**；
5. 商业模式围绕**"材料包/检测包"（material pack）**展开：试纸材料包按企业入库 → 激活 → 绑定锅炉，带有效期和二维码，是耗材销售 + 服务的载体。

### 目标用户（三级 RBAC）

| 角色 | 说明 |
|---|---|
| `platform_admin` | 平台管理员（炉保保运营方）：管企业、锅炉、材料包、检测标准、用户 |
| `enterprise_admin` | 企业管理员：管本企业的用户、锅炉、材料包 |
| `inspector` | 巡检员（企业现场人员，小程序端主力用户） |

### 核心业务流

企业入驻 → 锅炉建档（12 字段档案）→ 检测包入库/激活 → 绑定锅炉 → 发起巡检（试纸读数）→ 诊断 + 复测任务 → 月报聚合。

### 当前阶段判断

**灰测（试点）阶段**。识别不依赖 AI——灰测期一次人工录入软化水2项和炉水6项共8个读数（`recognitionSource: manual_gray`），照片仅上传留存，用于后续试纸读数算法训练和人工复核；未传读数时用样例值兜底（`sample_fallback`）。未来AI只输出读数，标准判断与处置仍由后端规则引擎负责。

### 鉴权

- 小程序：`POST /auth/wx-login`——配置 `WX_APPID/SECRET` 时调微信 `jscode2session` 换 openid；未配置时按 code 兜底到种子账号（H5 端 code=`h5-pilot` → `h5_user`）。

### 核心业务逻辑

**诊断引擎**（main.py 约 2400–2600 行），5 条组合规则：

| 规则 | 触发条件 | 诊断 |
|---|---|---|
| scale | 硬度高 + 磷酸根低 | 结垢风险 |
| corrosion | pH 低 + 亚硫酸根低 | 腐蚀风险 |
| concentration | 氯离子高 + 总碱度高 | 浓缩风险 |
| overfeed | 磷酸根高 + 亚硫酸根高 | 加药过量 |
| foaming | pH 高 + 总碱度高 | 汽水共腾 |

未命中组合规则时按单项异常生成。评分公式：`max(60, 100 - 6×预警项 - 4×未知项 - 8×高风险)`。

**状态机**：
- inspection：`created → uploaded → recognizing → done → submitted`
- material pack：`unactivated → activated → in_use → exhausted / expired / invalid`

**Onboarding 门禁**：登录响应带 `onboarding.required` / `canInspect`；材料包过期可进首页但禁止巡检；创建巡检时强制校验用户绑定、包已激活、包-锅炉-企业一致（7 重校验）。

## 六、数据流：一次巡检的完整链路

1. `login` 页 `wx.login` → `POST /auth/wx-login` → 返回 token + onboarding 状态（未绑包 → onboarding 扫码 → `POST /auth/complete-onboarding`）。
2. `inspect` 页：`POST /material-packs/verify` 确认包已激活且绑定当前锅炉。
3. `POST /inspections` → 后端 7 重校验 → 返回 inspectionId，状态 `created`。
4. 拍照 → `wx.uploadFile` → `POST /inspections/upload-image` → 图片存 `UPLOAD_DIR`，状态 `uploaded`。
5. 人工录入 6 项读数 → `POST /inspections/recognize` → 按锅炉额定压力匹配限值段 → 生成 items + 组合规则诊断 + score → 状态 `done`，写检测明细，自动生成复测任务；若是复测巡检则回填原任务为 `retested`。
6. `recognizing` 页轮询 `GET /inspections/result` → `result` 页展示 → `POST /inspections/submit` → 状态 `submitted`。
7. 后续：alerts 处理复测任务（complete/resolve）、records 查历史、`/reports/monthly` 出月报、`/dashboard` 聚合 KPI。
